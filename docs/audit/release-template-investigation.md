# Optimized Windows template qualification

The official Godot 4.6.2 Windows x86_64 release template was extracted from the official HTTPS multi-platform archive using verified HTTP ranges and ZIP CRC checks. The individual binary SHA-256 and source receipt are recorded in docs/provenance/windows-export-template.json; the whole archive hash was not claimed verified. A minimal independent exported project passes with that executable.

The original application package exited with Windows exception 0xC0000005 during startup under this optimized template. A debugger reproduces the failure. The root cause was the same initialization-order defect shown in the user's editor screenshot: ProductionUI creates the color panel before the viewer initializes its null configuration. The panel now waits for the viewer's ready signal and guards configuration access. The old UI suite injected a configuration and missed the real scene order; startup_checks.gd now exercises the unmodified main scene and restores saved preferences.

With that fix, the optimized template starts the actual main scene. Its separate source-free release qualification loads all 7,959,786 Bali/Suzuki Gaussians in 71.857 seconds locally, preserves independent model transforms and initializes the verified native ML bridge. The camera add-on also allocated two orphan MeshInstance3D objects when scripts were inspected without entering a scene; lazy creation inside its ready-owned visualization path removes the reproduced export RID leak while preserving both visualizations. Fresh qualification export has zero warning/error lines. Packaging no longer ignores the historical RID error.

Official templates disable path and script overrides ([Godot 4.6.2 main.cpp](https://github.com/godotengine/godot/blob/4.6.2-stable/main/main.cpp)). tools/qualify_release.py therefore exports a dedicated test scene in a separate package. tools/check_packaged_startup.py starts the real application package. Neither changes the working application entry point. No ImGui binary, font, Canvas backend or earlier failed depth-resolver experiment was promoted.

P.7.2 remains partially implemented for signing and broader real-device/platform qualification. The optimized-template startup failure and the reproduced export leak are fixed; see evidence/startup-*.log, camera-leak-*.log and release-bali-*.log/json/png.
