# GS compositions

Use **Scene → Save scene** to save the complete loaded composition as a `.pxrscene` file. Use the existing **Import** picker, drag-and-drop or recent-files list to reopen it. **Open scene** in Scene Navigator opens the same import flow. Interactive PLY and GSRES imports distinguish objects from environments; a `.pxrscene` restores/replaces the saved composition directly. Programmatic `import_path` and `load_new_splat_from_path` retain their existing append behavior for individual models.

The saved file references the original PLY/GSRES files. Keep those files available and unchanged. It does not merge, downsample or rewrite the Gaussian data. References include relative paths, with original absolute paths as a fallback, so moving a project folder together with its sources works. The viewer reports missing or changed sources rather than substituting different data.

Each model retains its stable identity, full world-space Transform3D matrix, import kind, name, visibility, cast/receive settings and complete population. Matrices preserve XYZ translation, rotation, nonuniform scale, reflection and shear without converting through Euler angles. The active/multiple selection, camera mode/pose/lens, orbit center, protection setting, image grade, renderer basis/scale and directional-light settings are also restored. GPU allocation preferences stay local; opening a scene that exceeds the current atlas is rejected without downsampling.

The model toolbar has a **vertical dotted grip on its left edge**. Drag it to move the toolbar; its normalized position is saved in the existing layout preferences. **System → Reset floating layout** returns it to automatic placement. The 67% UI scale, 33% background opacity, world-aligned gizmos and existing transform undo/redo remain in effect.

## Import an object or environment

The Import panel offers **Auto**, **Object**, and **Environment**. The same choice applies to Browse, file drop and recent files; the placement HUD also allows an override while a file loads or an object preview is pending. Auto uses the existing configurable 10-metre longest rendered-bounds threshold for each scan. Auto resolves once when the interactive import is ready, so later object scaling cannot turn it into an environment. This is a size heuristic, not semantic recognition: choose Object for a large vehicle or sculpture, or Environment for a small room.

**Object** retains surface placement. **Environment** skips placement and preserves its original full transform. After loading, the free-look camera enters the environment using the established sample-weighted horizontal centre and the 10th-percentile floor height plus 1.7 metres, subject to the existing floor/collider protection. Other loaded objects do not bias this entry calculation. A pending object changed to Environment first restores its initial source transform.

**Home view** returns to the selected environment, or the most recently loaded visible environment when an object is selected. **Frame selected** also enters a selected environment; Frame all retains the overall composition view. Scene Navigator includes the per-node type override and **Enter environment**. XYZ movement, rotation, scale, selection, undo/redo and floating toolbar movement remain available for all nodes. If a previously misplaced environment has already been confirmed, select it, use the existing **Reset transform** to restore its original pose, choose Environment, then **Enter environment**. Reset changes that selected transform; it does not rebuild the rest of the scene.

Opening a `.pxrscene` never runs interactive object placement or automatic environment entry: all saved matrices and the saved camera restore as authored. Version-one scenes without the optional `import_kind` field remain compatible and default to Auto. Scans have no added file-size cap and remain subject to the existing atlas capacity.

## Place an imported model

Choose a PLY/GSRES through Import, drop it into the viewport, or choose it from recent files. The complete model loads into the existing atlas while remaining hidden. A marker and, once ready, a bounds outline preview the placement. Move the pointer onto a GS surface, an ordinary collision surface or the reference floor. **Left click**, **Enter** or **Place here** confirms; **Escape** or **Cancel** removes only the pending import. **Keep original** completes the import at its original transform, including the established first-import framing behavior. Orientation and scale stay as imported; the existing transform tools handle later adjustments.

**Base centre** uses the full rendered-world bounding box. **Model origin** uses the imported origin. Bounds include captured ground patches and outliers, so the origin option and existing XYZ controls remain useful for asset-specific adjustment. GS placement uses the renderer's picked Gaussian point; it does not reconstruct a physical surface or add GS collision geometry. Ordinary surfaces require physical colliders. The reference grid remains a fallback and cannot override a visible GS hit, including scans below the guide floor. Other collision geometry competes by distance.

Camera navigation stays available. Confirmation is tied to its cursor/view snapshot, and asynchronous picks use request identities; moving the view invalidates an uncommitted confirmation. The hidden pending model cannot pick itself. Saved-scene commands wait for placement to finish, so an unfinished import cannot leak into a composition document. Clearing the scene cancels pending placement, and teardown releases its worker/atlas ownership. The placement HUD uses an authored scene and the shared theme/density, with a position that keeps the marker clear.

## Move the main control

Hold the **left mouse button on the PXRFusion medallion** and drag. A short click still expands/collapses the orbit; movement beyond a small threshold starts a drag. Both expanded and compact states save their current position in the existing layout file. Focus loss releases the gesture and camera blocker. Screen-edge clamping keeps the control reachable, and System's layout reset remains available. The startup layout establishes the correct dimensions before restoring the saved position.

The format is UTF-8, versioned, data-only JSON (`format: PXRFusion GS scene`, `version: 1`). It loads no scripts or Godot resource objects. Model transforms are 12 numbers: three basis columns followed by origin. Original files are fingerprinted with SHA-256 in bounded chunks; saved source identities are checked before replacing the atlas and against completed loads. Saving replaces the document atomically. Opening uses the existing disk-backed resident-atlas checkpoint for recovery, without allocating a second full GPU atlas or requiring the previous source files for rollback. A checkpoint failure preserves the existing composition; a GPU recovery failure retains the recovery checkpoint and reports its path.

Scene persistence is a local user action. Existing AI consent/action capabilities are unchanged. The format describes GS compositions and their view, not arbitrary Godot meshes, scripts, plugins, scan collision geometry or the complete authored Godot world. It references original files rather than embedding a portable asset bundle. There is no original-file size limit; admission remains governed by the atlas and instance capacity. There is no multi-user authorization service in this desktop application.

## Sky & time

Open **Light → Sky & time** for the existing Sky3D environment. Morning, Daylight, Sunset and Night presets set solar time and pause the day cycle; the time slider and clock share the live Sky3D value. Visibility switches control the sky, clouds, sun/moon lights and atmospheric fog. Cloud, sun and ambient energy remain directly adjustable. Expand Advanced for cycle duration/update rate, world camera/tonemap exposure, sky contribution, automatic exposure, moon/night ambient settings and celestial grids. **Restore scene atmosphere** returns to the settings captured when the scene started. The panel keeps the shared Polygonics theme, transparency, scale and floating-panel behavior.

Sky3D is the live owner. The UI binds its existing setters; an explicit field/range whitelist validates commands and saved data. `.pxrscene` includes the optional atmosphere snapshot and calendar/location context; older files without it stay compatible. Scene opening restores the snapshot before the existing saved sun pose. A running cycle resumes from the saved time and the existing system-clock synchronization, if enabled, continues to follow the system. Time presets/manual scrubbing stop system-clock synchronization so the selected time can take effect.

Sky3D lighting affects the world and enabled dynamic shadows; exposure can affect the whole rendered frame. Captured GS lighting/shadows are already baked into the data and cannot be removed or physically relit by moving the sun. Image studio remains the owner of the GS grade. These controls do not alter source splats, transforms, atlas settings or Gaussian-shadow opt-in. Scenes without a Sky3D node show an unavailable state. No new plugin is needed.
